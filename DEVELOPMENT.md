# Development

Daria Artemova's portfolio: a one-page site built with [Astro](https://astro.build), with content managed in [Sanity](https://www.sanity.io).

| Folder            | What                                                  | Package manager |
| ----------------- | ----------------------------------------------------- | --------------- |
| `frontend-astro/` | The site. Static build, deployed on Vercel.           | npm             |
| `cms/`            | Sanity Studio (project `wvlqa5od`, dataset `production`). | yarn / npm  |

## Run it

```sh
cd frontend-astro
npm install
npm run dev        # http://localhost:4321
npm run build      # type-check + static build into dist/
```

```sh
cd cms
npm install
npm run dev        # Studio on http://localhost:3333
npm run typegen    # regenerate frontend-astro/src/sanity/types.ts after schema or query changes
npm run deploy     # publish the Studio
```

## How it fits together

- The page reads all of its content from Sanity at build time with one GROQ query (`frontend-astro/src/lib/queries.ts`). Its result type is generated by Sanity TypeGen.
- The site is static, so content changes go live only after a rebuild. A Sanity webhook (manage.sanity.io → API → Webhooks) calling a Vercel deploy hook does this on every publish.
- Analytics: Vercel Web Analytics. Clicks on elements with a `data-track` attribute are sent as custom events.
